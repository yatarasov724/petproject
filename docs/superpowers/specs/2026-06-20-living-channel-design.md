# Sprint "Живой канал"

## Цель

Сделать посты в Telegram-канале визуально разнообразными и читабельными, чтобы канал не стыдно было рекламировать на Пульсе. Сейчас все посты одинаковые по структуре, языку и визуальному весу независимо от типа события.

## Проблемы

1. **Структура всегда одна** — `заголовок → Контекст → Следим за → тикеры` для любой новости
2. **Язык скучный** — AI пишет казённо, как официальный релиз
3. **Всё одного веса** — санкции выглядят так же как мелкая корпоративная новость

## Что меняем

### 1. Шаблоны под тип события (`formatter.py`)

EventType уже определён в `scorer.py` и вычисляется для каждого кластера. Нужно прокинуть его в `format_message()` и использовать для выбора шаблона.

| EventType | Эмодзи | Акцент |
|-----------|--------|--------|
| DIVIDENDS | 💰 | Выделяем факт дивиденда в заголовке |
| EARNINGS | 📊 | Акцент на цифрах (прибыль/выручка) |
| RATE_DECISION | 🏦 | Лаконичный макро-формат, без "Следим за" |
| SANCTIONS / WAR_ESCALATION | ⚠️ | Alert-стиль, без украшений |
| M_AND_A / IPO / SPO_BUYBACK | 🏢 | Акцент на сделке |
| CORPORATE / GEOPOLITICAL / прочее | без префикса | Текущий формат |

Конкретно: `format_message()` принимает `event_type: EventType` и выбирает `_format_<type>()` — отдельную функцию для каждой группы. Это изолирует логику и упрощает тесты.

### 2. Визуальный вес по score (`formatter.py`)

Score уже есть в `ScoreResult`. Используем для управления полнотой поста:

- **Score ≥ 50** → полный формат (summary + what_behind + watch_for)
- **Score 30–49** → средний (summary + what_behind)
- **Score < 30** → компактный (только summary + тикеры)

Это значит мелкие новости не загромождают ленту, важные — получают максимум контекста.

### 3. Живой язык в AI-промпте (`analyzer.py`)

Переписать system prompt:

- Убрать казённые метки "ЧТО ЗА ЭТИМ СТОИТ" / "НА ЧТО СМОТРЕТЬ"
- Задать голос: умный аналитик, говорит коротко и по делу, не боится мнения
- `summary` — одна сильная фраза, не пересказ заголовка
- `what_behind` — почему это важно для инвестора, а не нейтральный контекст
- `watch_for` — конкретный ориентир (дата, цифра), не общие слова

## Что НЕ меняем

- Логика pipeline (dedup, cluster, score, publish) — не трогаем
- Структура БД — не трогаем
- DM-формат (portfolio notify) — отдельная задача, не в этом спринте
- Digest-формат — не трогаем

## Затронутые файлы

- `backend/app/telegram/formatter.py` — шаблоны + score-based вес
- `backend/app/pipeline/orchestrator.py` — прокинуть `event_type` в `format_message()`
- `backend/app/ai/analyzer.py` — переписать system prompt

## Критерии готовности

- [ ] Посты с EventType DIVIDENDS, EARNINGS, RATE_DECISION, SANCTIONS визуально отличаются от обычных
- [ ] Пост с score < 30 компактнее чем с score ≥ 50
- [ ] AI summary звучит живее — нет казённых фраз типа "компания сообщила о"
- [ ] Все существующие тесты проходят
- [ ] Деплой на сервер, наблюдение за первыми 10 постами
